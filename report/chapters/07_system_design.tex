\chapter{SYSTEM DESIGN}

\section{System Architecture}

EduSphere AI follows a modern three-tier architecture with clear separation of concerns:

\subsection{Presentation Layer}
\begin{itemize}
\item \textbf{Technology:} Next.js 14 with React 18
\item \textbf{Rendering:} Server-side rendering (SSR) and static generation (SSG)
\item \textbf{Styling:} Tailwind CSS for responsive design
\item \textbf{State Management:} React hooks (useState, useEffect, custom hooks)
\item \textbf{Client-Side Routing:} Next.js App Router
\end{itemize}

\subsection{Application Layer}
\begin{itemize}
\item \textbf{API Routes:} Next.js API directory (/api/*)
\item \textbf{Business Logic:} TypeScript modules in /lib directory
\item \textbf{Middleware:} Authentication verification, input validation
\item \textbf{External APIs:} Judge0 for code execution
\end{itemize}

\subsection{Data Layer}
\begin{itemize}
\item \textbf{Database:} PostgreSQL 15+ via Supabase
\item \textbf{File Storage:} Supabase Storage (S3-compatible)
\item \textbf{Authentication:} Supabase Auth with JWT tokens
\item \textbf{Real-time:} Supabase Realtime for notifications
\end{itemize}

\section{Workflow Generation Algorithm}

\subsection{Document Context Analysis}

The workflow generation system analyzes multiple document attributes:

\begin{lstlisting}[language=JavaScript]
function analyzeDocumentContext(document) {
    const context = {
        type: document.type,           // notice, circular, policy, etc.
        scope: document.scope,         // department, college, institution
        department: document.department,
        category: document.category,
        creatorRole: document.creatorRole
    };
    return context;
}
\end{lstlisting}

\subsection{Workflow Rules}

\begin{enumerate}
\item \textbf{Notices and Circulars:}
    \begin{itemize}
    \item Department scope → HOD only
    \item College scope → HOD → Principal
    \item Institution scope → HOD → COE → Principal
    \end{itemize}

\item \textbf{Policy Documents:}
    \begin{itemize}
    \item Always require → HOD → Principal
    \end{itemize}

\item \textbf{Exam Schedules:}
    \begin{itemize}
    \item Require → HOD → COE → Principal
    \end{itemize}

\item \textbf{Timetables:}
    \begin{itemize}
    \item Department scope → HOD only
    \end{itemize}
\end{enumerate}

\subsection{Approval Matching Logic}

Approvers are matched by \textbf{role}, not by specific user ID:

\begin{lstlisting}[language=JavaScript]
async function findApprovers(requiredRole, department) {
    const approvers = await supabase
        .from('users')
        .select('*')
        .eq('role', requiredRole)
        .eq('department', department)
        .eq('status', 'active');
    
    return approvers;
}
\end{lstlisting}

Any active user with the required role can approve, providing flexibility when personnel changes occur.

\section{Security Design}

\subsection{Authentication Flow}

\begin{enumerate}
\item User submits email and password
\item Supabase Auth verifies credentials
\item JWT token generated with 1-hour expiration
\item Token stored in httpOnly cookie
\item Refresh token enables automatic renewal
\end{enumerate}

\subsection{Authorization Checks}

\textbf{Client-Side:}
\begin{itemize}
\item Route guards redirect unauthorized users
\item UI elements hidden based on role
\end{itemize}

\textbf{Server-Side:}
\begin{itemize}
\item JWT verification on every API call
\item Role validation against required permissions
\item Row-level security policies in database
\end{itemize}

\subsection{Data Protection}

\begin{itemize}
\item Passwords hashed with bcrypt (salt rounds: 10)
\item Sensitive data encrypted at rest
\item HTTPS enforced for all communications
\item Input sanitization to prevent XSS
\item Parameterized queries to prevent SQL injection
\item CSRF tokens on state-changing operations
\end{itemize}

\section{Deployment Architecture}

\subsection{Production Environment}

\begin{itemize}
\item \textbf{Frontend Hosting:} Vercel Edge Network
\item \textbf{Database:} Supabase (AWS Multi-AZ PostgreSQL)
\item \textbf{File Storage:} Supabase Storage (S3-compatible)
\item \textbf{CDN:} Vercel Edge for global distribution
\item \textbf{SSL:} Automatic HTTPS via Let's Encrypt
\end{itemize}

\subsection{CI/CD Pipeline}

\begin{enumerate}
\item Code pushed to GitHub repository
\item Vercel detects new commit
\item Build process initiated:
    \begin{itemize}
    \item Install dependencies
    \item Run TypeScript compilation
    \item Execute lint checks
    \item Build Next.js production bundle
    \end{itemize}
\item Deploy to preview URL (for branches)
\item Deploy to production (for main branch)
\item Automatic rollback on build failure
\end{enumerate}

\section{Scalability Considerations}

\begin{itemize}
\item \textbf{Horizontal Scaling:} Vercel auto-scales based on traffic
\item \textbf{Database:} Connection pooling and read replicas
\item \textbf{Caching:} Static page caching, CDN edge caching
\item \textbf{File Storage:} CDN distribution for global access
\item \textbf{Code Execution:} Rate limiting and queuing for Judge0 requests
\end{itemize}

\section{Conclusion}

The system design chapter presents a comprehensive architecture that balances performance, security, and maintainability. The three-tier architecture provides clear separation of concerns. The database schema supports complex queries while maintaining data integrity through foreign keys and constraints. The workflow generation algorithm automates approval routing based on intelligent context analysis. Component-based frontend design promotes code reusability. Security is embedded at every layer from authentication to data storage. The deployment architecture leverages cloud platforms for scalability and reliability.
